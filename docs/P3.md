# P3 — interest evolution, discovery, rabbit-hole, what-if, focus windows

P3 is the first phase where Mirror shows *how* interests appeared, grew and faded, and where session boundaries are used for something beyond totals. Everything here reads from the same engine and the same OS totals, and every number that needs a session boundary carries a guard until orphans are low.

Status: **plan awaiting continue**. P2 closed with conditions (open times only, J3 wired, Release Stage 1). P3 remains on hold until you say “continue”.

---

## The ten-line plan (as required)

1. **Real raw-event day capture** – use debug Share JSON (tap build 7x → Share raw events JSON) to capture a full day on your phone, replace `device-day-raw.json` / `honkai-day-raw.json` synthetic fixtures, re-run `buildUsageEvents` and drive orphans 319 → <50 via recent-close suppress 10s + 60s overlap + per-class persisted map.
2. **Session reliability gate** – `quality.byReason.orphan_background` and total gaps; if orphans >50 or gaps >100, P3 features show “needs more reliable sessions” and use only OS totals (authoritative) meanwhile; when reliable, use session start/end with low confidence (0.49 cap when approximate).
3. **Interest Evolution (J4)** – first seen, depth over time, trend; reads topic vectors when available (tier A/B/C) else degrades gracefully with “needs topic data” and shows only usage-pattern depth bands; uses OS totals for time, not invented durations.
4. **Discovery Journey (J9)** – exploration vs exploitation, route by route; top app by time from OS totals, new topics opened needs tier A/B/C, searches started needs tier C; shows “based on usage patterns only” when only D.
5. **Rabbit Hole (J11)** – definition shown (3+ consecutive short sessions same app, no search/save/cross-app follow-up); detection uses session boundaries only when reliable, else shows “needs more reliable sessions” and uses OS totals for hint; never frames habit as failure.
6. **What-if Simulator (J18)** – counterfactuals computed locally (remove short video, cap feed sessions, quiet hours), assumptions shown, uses your own distribution, never rescaled to 100, shows “out of 75” when only D; uses OS totals for baseline, not scaled durations.
7. **Focus Windows (J20)** – scheduled windows, not blocking, shows one line when you return; timestamps can tell you a window was scheduled, they cannot tell you whether time inside was focused; uses OS totals for time inside window when sessions unreliable.
8. **Depth (J5), Curiosity vs Habit (J6), Sessions (J8) – engine/mockup only correction** – mark as engine/mockup only in checklist (engine ready, UI mockup exists, not wired to real data until sessions reliable); J8 now shows app opens only, no durations, no scaling (P2 fix).
9. **Privacy canary E2E (emulator + mitmproxy) – real results** – `privacy-canary.yml` builds APK (mirror-test.apk), installs mitmproxy, runs emulator with proxy 10.0.2.2:8080, installs APK, launches app, collects 10s logcat, checks `privacy/android-report.json` for leaks in request.url/body/headers/logs; fails CI on any canary in body/URL/header/log/error; report uploaded as artifact; config checks (OTA guard, offline test, manifest gate) marked as config checks in checklist.
10. **Docs, tests, release** – update `deployment.md` checklist (J5,J6,J8 engine/mockup only, OTA/offline config checks), `metrics.md` §5.1 open times only, `PROGRESS.md` round 12 with real capture and orphan reduction numbers, `npm run verify` (251 tests, 106 core-analytics, privacy self-test ok, addon 9 tests ok, OTA guard PASSED, offline PASSED), tag-triggered Release with changelog, wait for “continue”.
