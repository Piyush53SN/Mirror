# P2 — the score, its reasons, and a way in

P2 is the first phase where Mirror computes something a person would recognise as
"what my week looked like". Everything here reads from the same engine, and the
engine's answers include the parts it could not measure.

Status: **delivered for review**. Release Stage 1 is **MANUAL** in this sandbox
(no JDK, no Android SDK, no signing identity).

---

## Step 0 — Gradle compile and the merged-manifest gate

**MANUAL. Not run here.** The sandbox has no JDK and no Android SDK, and the
build needs `platforms;android-36` plus build-tools.

```
$ bash scripts/android/build-and-gate.sh
build-and-gate: cannot build — preconditions missing:
  - java (JDK 17+)
  - ANDROID_HOME or ANDROID_SDK_ROOT (Android SDK ...)
exit 2
```

The wrapper is the *only* path to a merged manifest: it refuses to reuse a stale
one, runs `prebuild` when `android/` is missing, compiles, and then hands the
merged `AndroidManifest.xml` to `scripts/android/check-merged-manifest.mjs`.
Six tests (`tests/android-build.test.mjs`) cover the refusal paths; twelve
(`tests/android-manifest.test.mjs`) cover the audit itself, against the **merged**
manifest rather than `app.json`.

On a workstation:

```bash
make android-build      # Gradle assembleDebug + gate; exits 2 without JDK/SDK
make android-manifest   # re-audit an existing merged manifest
```

Step 0 is complete when that command exits 0 on a machine with the SDK. It has
not been, and this phase does not pretend otherwise.

## The scoring engine

`packages/core-analytics/src/scoring.ts`, 17 tests.

| factor | max | how it is measured |
| --- | --- | --- |
| `session_length` | 25 | share of attended time in sittings of 8 minutes or longer |
| `deliberate_share` | 20 | share of labelled time marked intentional; needs ≥ 5 decisive labels |
| `switching` | 15 | `15 × 20 / (perHour + 20)`, a saturating curve, not a cliff |
| `late_night` | 15 | share of attended time between 23:00 and 05:00 local |
| `topic_depth` | 25 | breadth of scorable topic vectors; needs ≥ 5 |

Rules the engine keeps:

- **A missing part is missing.** `value: null`, `max` reduced by exactly that
  factor's maximum, and a reason saying so. It is never a zero and never
  re-weighted to fill 100.
- **Two maxima exist.** Usage only (tier D) tops out at **75**; with topic data it
  is 100. Both are honest; the screen prints `/ 75` when that is all it has.
- **The parts close.** `Σ points === value`, asserted in the suite.
- **Zero sessions** returns `{ score: 0, level: 'none' }` with confidence
  `none` — no NaN, no divide-by-zero, and no "0 out of 75" presented as a result.
- **Placeholders are excluded.** A vector from `placeholder-ngram-v1` can never
  count as semantic understanding.
- Partial coverage adds a reason: *"The score covers 75 of 100 points; the
  missing parts are listed, not estimated."*

### Signal confidence

`confidence` carries `score` (0–1), `level`, `coverage`, `sessions`,
`decisiveLabels`, and `reasons[]`. Every reason is a sentence a person can act
on ("Only 3 of the 5 decisive labels needed…"), and the Why sheet lists all of
them rather than showing a single percentage.

### One source of numbers

`packages/ui/screens/personas.ts` no longer carries `iqs` or `whyParts`.
`packages/ui/screens/scores.ts` builds a deterministic demo week from the persona
id (mulberry32, fixed week start, about 280 sittings) and runs the **real** engine:
`scoreIqs`, `sessionBands`, `curiositySplit`. Personas supply curiosity inputs
such as `lateNightShare`; they cannot supply a score.

Current probe values (usage-only, confidence 0.97, 60 intent labels):

| persona | IQS | curiosity / habit |
| --- | --- | --- |
| Ananya | 49 / 75 | 44.8 / 52.6 min |
| Rehan | 60.1 / 75 | 148.9 / 96.0 min |
| Mei | 66.6 / 75 | 320.0 / 126.0 min |

Consequence: the old mockup's `/126` denominator cannot come back. The Why sheet
receives `maxScore={iqs.max}` from the engine.

## The import screen

**Not a Section J item.** Section J has exactly 28 items and this is not one of
them, so it ships as `EXTRA_SCREENS` (`X1`, slug `import-export`) and the gallery
renders it under "P2 additions · not in Section J". Adding it to `SCREENS` would
make the inventory test a lie.

It is a genuine UI over the P1b-2 importers, not a drawing:

- `packages/ui/screens/demoImport.ts` holds a small Reddit export, an in-memory
  `ImportStorePort`, and calls the real `preview()`.
- `DEMO_PREVIEW` is the frozen result the screen renders, and
  `packages/ui/tests/import.test.mjs` **recomputes it** and asserts equality. If
  the parser or the bundle changes, the test fails before the screen drifts.
- The same test runs `commit()` twice: 21 fresh items the first time,
  `nothing-new` the second, and `no-consent` when the grant is dropped.

The screen shows the grant subject (`export:reddit-export`), what revocation
deletes, and one refused row rather than hiding it.

### The large-Takeout note

A decade of YouTube history is one `watch-history.json`, often 50–200 MB. Mirror
reads **one file at a time** and enforces **`MAX_FILE_CHARS` = 64 Mi characters
(67.1 million characters)**. Above that the file is **refused with a warning**, not
truncated, and the preview says so; the person is asked to request a shorter date
range or split the archive.

Why refuse instead of stream: a partial read would make a quiet week look quiet.
The parser API takes a string today, so streaming is a P5 refinement; the cap is
what keeps the failure honest in the meantime. The UI sentence is generated by
`oversizedFileSentence()` and tested, so the copy cannot drift from the guard.

There is no ZIP reader by design — the person unzips the export and selects the
folder. That is a documented limitation, not an oversight.

## Tests

`npm run verify` → tokens, three typechecks, lint, all suites, secret scan.
This phase added 17 scoring tests, 6 import-screen tests and 4 release tests.

The four brief edges are the first four scoring tests:

- **empty** — no sessions, no score, `null`, confidence `none`;
- **zero** — sessions but nothing measurable, still no invented number;
- **single event** — one sitting scores what it can and says what it cannot;
- **all sessions < 8 s** — session-length points are 0 and *that is measured*,
  not missing.

Property tests assert, over random inputs, that parts always sum to the score,
that the score stays inside `[0, max]`, that session ids stay inside the
validator's alphabet, and that sessions never overlap themselves.

## Release Stage 1

**MANUAL.** There is no keystore, no JDK, no Android SDK and no EAS login in this
environment, so no signed artifact was produced.

Automated here:

```
$ make release-stage1
Release Stage 1 preflight
  ok   package id dev.mirror.app
  ok   versionCode 1
  ok   version 0.1.0
  ok   production → AAB
  ok   versionCode auto-increments
  ok   submit track internal
  ok   no keystore in the tree
Automated checks passed.
Built artifact: NOT FOUND — no APK/AAB exists in this checkout.
```

Manual steps (also printed by the script):

1. Create the upload keystore **outside** the repository.
2. Upload it with `eas credentials`; keep the password in a password manager.
3. `make android-build` — the merged-manifest gate must exit 0.
4. `make build-production` — signed AAB.
5. `apksigner verify --print-certs <artifact>` and install the internal APK.

The preflight **fails** (exit 1) on a wrong package id, a missing AAB profile, or
a keystore committed to the tree. It never exits 0 claiming an artifact exists.

## Limitations

- **Step 0 and Stage 1 have not been executed.** Both need the Android SDK; both
  are labelled MANUAL rather than reported as passes.
- **The demo week is synthetic.** It is deterministic and runs the real engine,
  but it is not device data. The device path (UsageStats → store → engine) is
  wired in P1b and exercised by unit tests, not by an on-device run.
- **Streaming imports are not implemented.** Files above 64 Mi characters are
  refused; the parser holds one file in memory.
- **Sessions are per app.** A sitting that switches apps is several sessions;
  switching rate is computed across them. Merging app switches into one sitting
  is a P3 question once intent labels exist for cross-app sessions.
- **No i18n/RTL pass** yet; copy is English.
- **The gallery is 100 frames**, not 96: the four import-screen frames are new
  and are listed separately from Section J.
